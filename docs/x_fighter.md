# X-战机 · SGH-X458 源码版

从 `X458ZCEK1.s3` 提取关卡、敌机、武器、Boss、计分、排行榜和 RGB565 绘图逻辑。桌面运行版使用 Python，读取 `assets/runtime-data.bin` 中的图像、调色板和常量表。默认使用简体中文，游戏内部保留 128×160 像素。

## 启动

双击项目根目录 `run.bat`，在启动器中选择《X-战机》和画面尺寸。默认 400×500，另可选择 128×160、200×250、300×375。四档均保持 4∶5，并使用最近邻缩放。脚本使用项目根目录的共用 `.venv`。

启动器提供「标题菜单」「战斗进度」「Boss 战」三个入口。战斗进度按 Boss 入场前的地图推进量估算。选 Boss 战或把战斗进度设为 100% 时，从所选关卡 Boss 入场音乐响起前 2 秒的战斗画面开始（1× 倍速）。随后按原流程播放音乐，Boss 满血入场。战斗进度和 Boss 战可选速度+、攻击+或防御+战机。

启动器提供无敌、开局武器强化、初始护盾开关和炸弹数量，普通子弹自动发射。初始装备只在本次启动进入的第一场战斗应用一次。炸弹默认 3 枚，可选 0–10 枚。游戏倍速可选 0.5×、0.75×、1×、1.5×、2×，默认 1×，音频采样按原速播放。跳场景、变速和自定义练习的成绩保存在 `.local/X-Fighter/practice-scores.bin`。

| 场景 | 原手机键 | 桌面键 |
|---|---|---|
| 菜单 | `1` 开始、`2` 最高分数、`3` 按键信息、`4` 继续已暂停的游戏 | 数字键。Enter 开始 |
| 封面 | 任意有效键进入选机 | Enter |
| 选择战机 | `1` 向上、`7` 向下、`9` 确认 | ↑ 或 W、↓ 或 S、Enter |
| 战斗 | `1` 上、`4` 左、`5` 右、`7` 下 | 方向键或 WASD |
| 导弹／核弹 | `6`／`9` | Z 或空格／X |
| 暂停／继续 | CLR | Esc 或 Backspace |
| 高分录入 | 手机数字键多击选字、确认 | 直接输入字母、数字或空格，←／→ 移动光标，Backspace 删除，Enter 保存 |

游戏默认音量为 50%，可在启动器里调整或静音。直接运行 `python -m sgh_x458.x_fighter` 时，`--mute` 静音，`--size 300x375` 选择窗口尺寸，`--speed 1.5` 使用 1.5 倍速，`--language 0` 为英文，`--language 2` 为繁体中文。标准游戏的排行榜保存在项目根目录的 `.local/X-Fighter/scores.bin`。

游戏窗口关闭文本输入，可以在 Windows 中文输入法开启时使用 WASD、Z 和 X。长按移动键期间，单次导弹和核弹指令优先执行，之后恢复长按移动。

## 源码

代码位于 `src/sgh_x458/x_fighter/`。`game_rules.py` 用具名函数实现战斗帧调度、移动、拾取、核弹、编队触发、坠机和后备机规则。`game_flow.py` 是其余固件例程的静态 Python 转换，保留地址标签和低层状态布局，便于逐段核对。`game.py` 接入专属规则，共用的 `sgh_x458/runtime/` 提供状态存储、设备服务和 RGB565 位图绘制。`layout.py` 保存资源路径、ROM 区间和状态地址，`practice.py` 负责场景跳转，`audio_mix.py` 负责专用播放滤波。初始后备机和移动步长已有源码接口，启动器尚未接入自定义设置。

## 提取与校验

| 路径 | 内容 |
|---|---|
| `assets/manifest.json` | 运行时音频索引，以及离线导出的原地址、文件长度、图像锚点、调色板和哈希 |
| `assets/runtime-data.bin` | 运行用的索引色图像、调色板和固件常量 |
| `assets/audio/original/` | 15 段从 ROM 原样切出的 `.mmf` |
| `assets/audio/firmware_wav/` | 由 15 段固件 SMAF 渲染的 48 kHz、16 位 PCM |
| `assets/audio/playback.json` | 固件事件、调用点、播放文件和哈希的对应关系 |
| `.local/x-fighter-extract/` | 项目根目录下的按需导出。含 197 组索引图与 PNG，以及调色板、原始表和关卡地图 |

PNG 默认使用固件的第 3 组调色板和第 0 变体。桌面按固件事件播放 PCM，支持单通道、暂停和恢复。调色板切换见[封面与激光坠机的定时](#封面与激光坠机的定时)。

```powershell
.\.venv\Scripts\python.exe -B -m tools.x_fighter.verify_source
.\.venv\Scripts\python.exe -B -m tools.x_fighter.verify_source --compare-rom --all-stages
.\.venv\Scripts\python.exe -B -m tools.x_fighter.verify --all-stages
```

后两条命令需要原始刷机镜像和 `pip install -e ".[tools]"` 安装的 Unicorn。在项目根目录运行 `python -m tools.x_fighter.extract_assets` 将完整资源导出到 `.local/x-fighter-extract/`，可用 `--output` 指定其他位置，运行 `python -m tools.x_fighter.lift` 重做静态转换。离线重新合成 WAV 时，用 32 位 Windows Python 执行 `python -m tools.render_audio <ma3smwemu.dll>`，并更新 `playback.json` 中的 WAV 哈希。渲染器来源及对照数据见 [图像与音频](#图像与音频)。

## 固件逆向记录

### 入口与执行路径

共用地址、固件哈希和 S-Record 格式见[固件与共用调度](firmware.md)。

| 地址 | 《X-战机》中的用途 |
|---|---|
| `0x5995B0` | G58 AirShooting 注册记录。游戏函数指针 `0x235A35` |
| `0x235A34` | 游戏回调。事件 0 绘制标志，1 初始化，3 恢复定时器，4 更新场景，5 处理按键，9／10 绘制按键信息 |
| `0x22B100` | 读取位图锚点，通过格式表分派绘制函数 |

`tools/oracle.py` 与 `tools/x_fighter/oracle.py` 通过 Unicorn 执行原版 ARM，供离线验证。桌面版由 `game.py` 运行 Python 逻辑并提供宿主服务。`tools/x_fighter/lift.py` 借助共用的 `tools/lift.py`，按同目录 `trace.json` 的块地址及读数据地址定位例程，生成 `game_flow.py` 和单独的数据包。绘制分发表在 ROM 的 `0x6AD00C`。桌面端把 RGB565 三个分量线性展开为 8 位，窗口使用最近邻缩放。键盘长按在每次战斗更新前派发最近按下的有效键。

### 玩法逻辑

启动初始化直接影响游戏行为。已验证的例子有掉落的横纵位移表，以及排行榜字符指针。后者在 ROM `0x6AD064–0x6AD118`，启动时复制到 RAM `0x0103EF18`，指向 ROM `0x22B310–0x22B3C4` 中的字符。只复现函数路径会漏掉这类初始化，且 Python 与精简 ARM 对照器可能同时表现异常。

游戏状态位于 RAM `0x0103F4CC`。`0x235A78` 的分发表把状态 0、2、3、4、5 分别分发到封面、选机、关口过渡、战斗与结束流程。选机可在三个机型间切换，`0x234448` 从 ROM `0x5AD8B4` 装载对应机型参数。战斗计时器由 `0x234716` 注册，名义间隔 250 ms，换算后为 55 个手机定时刻度。关口画面到战斗的逻辑阈值为 10 次更新。

| 地址 | 原版实现 |
|---|---|
| `0x234724` | 方向键每次移动 10 像素，`6` 导弹，`9` 核弹 |
| `0x230744` / `0x230768` | 按机体宽高限制玩家移动范围 |
| `0x2305D8` | 普通武器自动发射和武器强化状态更新 |
| `0x22FE50` | 核弹使用条件、库存扣除、画面效果初始位置及音频 |
| `0x22FFFC` | 更新两个掉落槽的位置，按两组 36 步表移动并判定拾取 |
| `0x234480` | 更新关卡滚动和波次计数，按地图表字段触发编队 |
| `0x5ABFC8–0x5AD7D4` | 连续三组地图表，每组 57×9 个小端 32 位值。JSON 保留 ROM 顺序 |
| `0x234370` | 按 Boss 类型分发三套状态更新，再处理与玩家的接触 |
| `0x2302C4` / `0x2355A4` | 玩家坠机、爆炸动画、后备机扣除和 Game Over 转移 |
| `0x23589C` | 原版战斗图层绘制与提交 |
| `0x22B440` | 排行榜成绩插入，随后进入原版录入界面 |

掉落表在 ROM 的 `0x6AD6BC`（纵向）和 `0x6AD74C`（横向），初始化时拷贝到 RAM 的 `0x0103F570` 和 `0x0103F600`。每次更新将横向表值加到 X，将纵向表值加 1 后加到 Y，再推进相位。开始下落时单次垂直位移最高为 5 像素。完整周期净向下 36 像素，横向回到起点。早期桌面版漏载这两张表，导致道具匀速直落。

子弹表位于 `0x5ADB9C`，单发伤害通过子弹记录的 `+0x08` 字段扣除目标 HP。已用原版 ARM 和 Python 对照测试三种机型的自动发射及命中，包含强化前后、普通敌机和 Boss。按选机顺序，三种机型的单发伤害分别为 5、10、15，强化后为 10、15、20。速度型每个战斗更新发射 1 枚子弹，强化前后频率一致。

三关探针在波次计数 49 观察到 Boss 进入活动状态，读到的初始 Boss HP 依次为 900、2000、3000。玩家初始有 3 架后备机，最后一架坠毁后后备机计数变为 −1。源码版在 `game_rules.py` 保留具名规则和字段。其余例程经过静态转换，部分函数仍只有固件地址和底层变量。

### 封面与激光坠机的定时

打开菜单时共用调度器 `0x20D88A` 传入 500 毫秒（`0xFF + 0xF5 = 500`），`0x20DBD2` 同样为 500；帮助等界面在 `0x20D968`、`0x20DA20`、`0x20DAB8` 传入 1000 毫秒（`0x7D << 3`）。进入游戏时 `0x234710` 向主定时器传入 250 毫秒（`0xFA`）和重复标志，继续游戏的 `0x235BBE` 也传入相同参数。经 `0x20D188 → 0x228174` 换算：`0x228182–0x228186` 计算 `13 × 毫秒 + 59`，`0x228194` 载入 60 并调用 `0x14B3A4` 取商，即 `(13 × 毫秒 + 59) // 60` 个系统刻度。250 毫秒得 55 刻度，500 毫秒得 109 刻度。系统定时器 `0x148AC` 在 `0x1499A–0x1499E` 读取 `0x01000450` 的当前计数，再加刻度数写入定时队列。按固件的换算，每刻度为 `60/13` 毫秒，与 GSM TDMA 帧周期一致。[ETSI TS 145 002 §4.3.1](https://www.etsi.org/deliver/etsi_ts/145000_145099/145002/04.05.00_60/ts_145002v040500p.pdf)

系统到期后由 `0x154948` 向手机界面任务投递事件。界面任务在 `0x1FB8CC` 先执行游戏更新，再在 `0x1FB8F6` 重新注册定时器。ARM 对照将首次期限设为第 10055 刻度，并让回调分别消耗 0、12、28 刻度，读到的新期限分别是 10110、10122、10138。重挂时基于当前计数。下一次到期还要等界面任务取出消息，因此固件能确定每次重挂后的等待为 **3300/13 毫秒**，两次可见或可听事件之间还包括游戏处理与消息调度。

#### X 标志的明暗节奏（固件决定）

两处 X 共用 RAM `0x103E820` 的计数器：每个 slot 0 主定时器事件先 `+1` 再对 `0x13B0`（5040）取余，随后 `0x14B3A4` 分别对 3 和 6 取余，`count mod 6` 作为变体号传给 `0x22A2C0`，把 ROM `0x599D70` 对应变体的 182 个 RGB565 色值拷到 `0x12DA3E0`。X 使用索引 3 的颜色，于是六档循环变亮、变暗。菜单走 `0x20D21C` 的 `0x20D240–0x20D258`，之后 `0x20D25C` 给游戏回调发事件 0 重绘；游戏内走 `0x20D9F8 → 0x20D544` 的 `0x20D56C–0x20D584`，仅当定时器参数为 0 时更新。两段代码是同一套计数逻辑的副本。

| 界面 | 主定时器注册 | 名义间隔 | 刻度 | 每档 | 六档一轮 |
|---|---|---|---|---|---|
| 标题菜单 | `0x20D88A` | 500 ms | 109 | `6540/13` = **503.077 ms** | **3018.462 ms** |
| 封面／游戏 | `0x234710`、`0x235BBE` | 250 ms | 55 | `3300/13` = **253.846 ms** | **1523.077 ms** |

Unicorn 执行原版固件时记录了以下时序。菜单的变体切换发生在 `t = 6540, 13080, 19620, 26160, 32700` 时间单位（每 6540 一档，变体 2→3→4→5→0）；封面的 `0x20D544` 发生在 `t = 30600, 33900, 37200, 40500 …`（每 3300 一档，变体依次 0→5 循环）。菜单与封面的周期比为 **109∶55**，约为 **2∶1**。桌面 `runtime/session.py` 的 `timer_interval()` 复刻 `0x228174` 的换算，`advance()` 按该间隔重挂 slot 0，两处均不再附加节流；真机可见事件之间另有界面任务处理与消息调度开销，桌面只复刻固件可确定的定时器间隔。

- **Boss 激光击杀**。每次更新由 `0x233954` 检查活动光束，仍判为致命命中时经 `0x2337FA → 0x2302C4 → 0x2280D8` 请求播放 `0x5A7E46`。连续战斗帧都触发时，名义等待为一拍，即 **253.846 毫秒**。音频驱动在 `0x1537E4` 停止仍在播放的旧声，再在 `0x1537FA` 请求单次播放。ARM 测试确认该次调用收到地址 `0x5A7E46`、长度 305 字节和单次播放参数。
- **单段坠机声**。`5A7E46.mmf` 的 `MTR` 中 `TimeBase_D` 和 `TimeBase_G` 都是 `0x02`，即 4 毫秒。`Mtsq` 中的最后音符门限在 **376 毫秒**到期，序列在 **380 毫秒**结束。现有桌面 WAV 的长度为 **360 毫秒**。原机参考录音的五个起音经波形对齐，相邻约 **377、392、378、379 毫秒**。桌面用 382 毫秒近似录音里的重触发间隔，序列长度和重触发由不同的代码决定。这是唯一仍在桌面拉长主定时器的适配（`game.py` 的 `HANDSET_LASER_DEATH_MS`，仅在 `handset_timing=True` 且激光连续致命时生效），只影响战斗坠机音效，与菜单／封面的 X 闪烁无关。[Yamaha SMAF 3.05 §4.4.1](https://img.atwiki.jp/mmfuta/attach/19/78/SMAF3.05.pdf)

### 图像与音频

图像段 `0x59DCD0–0x5A4FEC` 连续解出 182 个记录，随后紧接 15 个 SMAF 容器，结束于 `0x5ABDF5`。其他 15 张共用菜单图由三种语言的菜单、帮助和排行榜流程追踪得到。所有区间的右端均不包含在内。

图像头为格式、宽、高、锚点 X、锚点 Y。格式 5、6、7 分别是 1、2、4 位连续位流，像素从高位开始，数据补齐至 16 位，颜色索引通过图像自身的查找表映射到 RGB565 调色板。格式 8 使用 8 位全局索引。全局索引 4 表示透明。调色板基址是 `0x599D70`，每组有 6 个变体，每个变体包含 182 个 RGB565 色值。

桌面首页单独减弱四枚数字键图块的绿色，没有可继续的进度时灰显「4 继续游戏」。从标题菜单开局时，关闭窗口会保存当前局面，重开后在标题菜单按 4 恢复。首页调整只发生在窗口显示层，固件帧缓冲用于对照测试。

开始游戏后，星空封面由 `0x234780` 绘制，X 标志随 `0x103E820` 计数的六档调色板循环变亮、变暗。桌面保留固件六档色值和顺序，节奏由固件主定时器决定（菜单每档 503.077 毫秒、封面每档 253.846 毫秒），与离线 ARM 对照逐帧一致。

已从调用验证 `5A62F0` 用于封面和最终胜利，`5A7F77` 用于切换机型，`5A4FEC` 用于关口进入，`5A8489` 用于玩家发射导弹，`5A800D` 用于核弹，`5A7E46` 用于玩家坠机，`5A7066` 用于 Game Over。`5A6FA8` 后紧接着按道具类型发放火力强化、护盾或核弹。播放事件、调用点和 WAV 哈希见 `assets/audio/playback.json`。

第一关 Boss 的更新例程在 `0x233AFE` 和 `0x233B4A` 调用导弹和激光发射音效。第二关的 `0x233B90` 例程在对照测试中分别调用了 36 次导弹生成和 4 次激光生成，两种发射音效均未触发。

用真机录音（未随仓库发布）比较时长和频谱。早期通用渲染器把封面曲合成了 25.48 秒，录音为 7.37 秒。改用 Yamaha MA-3 渲染后，数字输出含 80 毫秒固定静音预卷约 7.28 秒，发布文件移除了预卷和末尾的全零采样。Game Over 也从 25.48 秒变为约 7.42 秒，录音为 7.52 秒。对齐后比较录音频谱，15 段相对于早期渲染均有改善，普通子弹命中的录音仍和数字输出相差较大。

`tools/render_audio.py` 校验原始 SMAF 的哈希，并在 WinMM 输出点采集 MA-3 渲染器生成的 48 kHz、16 位立体声 PCM。离线使用的 DLL 的 SHA-256 为 `fe23024433abc95e0d94c9df6ec95f093447d30ec47150f3042259b261c779a5`。桌面播放从导出的 WAV 加载。[MA-3 渲染器来源](https://github.com/denjhang/libsmaf/tree/3884e2fca1b5b82480ef9bd809658d9e08fb8bd5/ma3-windows-x86)

对照真机录音的频带能量后，桌面在播放时降低音量，并针对本机中弹、两种爆炸、本机及 Boss 的导弹发射这五段削减过重的低频。滤波在声音首次加载时进行，原始 SMAF、PCM 和事件时序保留。[数字滤波公式](https://www.w3.org/TR/audio-eq-cookbook/#hpf)

复核确认 15 份 SMAF 均与固件字节一致。同一渲染器再次导出，12 个 WAV 的 PCM 逐样本一致，包含玩家坠机。敌机击毁、拾取和核弹三段在复渲染时有样本差异，时长一致。

X458ZCEK1 自身的日志在 `0x117704` 标识 `YMU762_VolumeManage`，在 `0x153BC0` 标识 `YMU762_StopMelody`。`0x1176E8–0x1176F0` 还记录了 `EQ_SP_Vol`。YMU762 的数字合成以 48 kHz 运行，扬声器有独立的模拟均衡和功放。15 个游戏 WAV 的左右声道逐样本相同。用模拟器音量参数复测时，玩家坠毁音效约 10.4% 的采样落在两端峰值，调整参数只改变峰值幅度，削顶比例基本相同。目前保留现有数字渲染，X458 扬声器的模拟频响还没有可验证的校准值。[Yamaha YMU762 数据手册](https://pdf.dzsc.com/YMU/YMU762.pdf)

### 验证范围

- 对比 197 张导出图与固件绘图例程输出的 RGB565 像素，检查透明、裁切和镜像，并检查 15 段原始音频与 ROM 字节一致。Windows 检查覆盖四档尺寸、WASD、方向键和 SDL 对 15 个 WAV 的解码。调色板保留固件值，原机屏幕的实测色彩仍未校准。
- 正常规则下验证攻击、阵亡、Game Over、成绩录入和读取。三关通关探针仅在测试中屏蔽玩家坠机例程，实际推进到第三关 Boss HP 为 0 并进入成绩录入。
- Python 源码版以 ARM 对照版为基准完成三种语言的正常流程验证、三关探针的逐帧及音效事件比对，并检查了两个完整掉落周期、拾取和出界。原版格式化库仍有少量静态分支未覆盖。
- 第三关全屏 Boss 的 820 个活动帧与固件输出逐像素一致。录像中的 Boss 同时有蓝色和紫色区域，桌面保留了固件的 RGB565 色值。
- 以各自从选机到第一关 Boss 清楚可见为参照，桌面验证约为 4 分钟，原机录像约为 5 分钟。差值还需区分手机处理耗时、玩家操作和录像时间轴。
- 原机逐帧同步、长按的精确重复节拍、音效混音优先级和扬声器输出仍需真机对照。三关正常操作的完整通关也有待验收。
